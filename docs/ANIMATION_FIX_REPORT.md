# Расследование невидимых анимаций — 0.5.5

> Исторический отчёт от 20 октября. Последующее независимое расследование, измерения в действующем Foundry и проверки OBS описаны в [ANIMATION_FORENSIC_REPORT_RU.md](ANIMATION_FORENSIC_REPORT_RU.md). Ограничения и утверждения ниже относятся к прежнему этапу, а не к новым результатам.

Дата: 20 октября 2026. Изменения внесены непосредственно в установленный модуль:
`C:\Users\Lev\AppData\Local\FoundryVTT\Data\modules\modular-stream-overlay`.
`Config/options.json` подтверждает `dataPath: C:/Users/Lev/AppData/Local/FoundryVTT`, manifest — `modular-stream-overlay`, Foundry v14. Новый проект, карусель или демонстрационная система не создавались.

## Подтверждённые причины

1. **Браузер на этой машине действительно запрашивает уменьшение движения.** Через браузерный инструмент, без изменения настроек, получен результат `window.matchMedia('(prefers-reduced-motion: reduce)').matches === true`. Дополнительно Windows сообщает `MinAnimate=0`. Production-контекст в `scripts/main.js` при включённом **Respect reduced motion** намеренно блокирует все эффекты; эта настройка и **Enable overlay animations** по умолчанию включены. Карусель при этом правильно продолжает менять содержимое мгновенно. Значение сохранённой настройки конкретного мира не прочитано: запущенный мир был недоступен. Поэтому текущий браузерный запрос подтверждён, а применение настройки конкретным Foundry/OBS-клиентом ещё требует проверки в нём.
2. **Принятие команды ошибочно выглядело как успешное воспроизведение.** Контроллер возвращал `disabled`, а тестовая панель всё равно писала `played`. Прежняя диагностика записывала запрос до проверки блокирующих условий. Она не доказывала старт или изменение изображения.
3. **Pulse имел неправильный визуальный смысл.** Он менял только прозрачность, слабо и почти так же, как Flash. Масштабирования 1 → 1,12 → 1 не было.
4. **Цель целого виджета находилась внутри обрезающего контейнера.** Для комбинированной карточки Play/Preview выбирали внутренний, уже масштабированный `.mso-stage` текущего Actor. Его увеличение обрезалось границами представления. Весь виджет теперь анимируется на внешнем элементе, сохраняющем геометрию и поворот.

Не найдено подтверждения, что обычная смена страницы немедленно уничтожала её DOM: исходный код сохраняет уходящую страницу до завершения её gate-анимации. При смене Actor старая карточка полностью выходит перед входом новой. Последовательность, единый таймер, подготовка Actor и разделение данных не переписывались.

## Проверки и ограничения

Из канонической папки выполнены `npm run check` (73 JavaScript-файла) и `npm test`: **369 тестов, 368 прошли, 0 ошибок, 1 пропущен**. Пропущена существующая проверка символических ссылок/junction: Windows не разрешает создать тестовую ссылку. Итог последнего запуска записан в `work/animation-fix-full.log`.

Автоматические проверки подтверждают: Pulse содержит масштаб 1,12 с сохранением поворота; Flash/Glow имеют отличающиеся свойства; вход/выход наследуют настройки; уходящая цель подключена и не скрыта до завершения; повторный вход отменяет старый выход; временные эффекты не меняют сохранённые координаты; reduced motion/disable останавливают эффекты; правильный цикл персонажей и страниц сохраняется; рендер сообщает `render-interrupted`.

**Новые визуальные проверки пока не пройдены.** Локальный проверочный сервер не удалось открыть: среда отклоняет соединения с `127.0.0.1:30001` (`socket access forbidden` / `ERR_CONNECTION_TIMED_OUT`), в том числе после повторной попытки по сообщению пользователя о включении доступа. `http://localhost:30000/` ответил `ERR_CONNECTION_REFUSED`; действующий мир Foundry не был доступен. Предпочтение браузера удалось прочитать на пустой вкладке без сети.

Поэтому в этой работе **не измерены настоящие промежуточные computed opacity, scale или displacement на production DOM**, не сняты кадры анимаций, не подтверждена визуальная работа в полном редакторе Foundry или OBS. Проверки с поддельным DOM и сами события WAAPI не выдаются за такие доказательства. Старая браузерная проверка 0.5.4 также не заменяет эти измерения.

## Как проверить в существующем демо

1. Перезапустите Foundry, обновите GM-клиент и Browser Source OBS. Откройте **Open Overlay Editor → Open Demo Overlay**. Сброс демо не требуется.
2. В **Animation Test Controls** выберите карточку и **Editor preview**, нажмите **Pause Carousel**. Проверьте **Enable overlay animations**. Если панель сообщает reduced motion, это намеренная блокировка. Если вы хотите разрешить анимации оверлея вопреки системному предпочтению, осознанно отключите **Respect reduced motion** в настройках модуля. Эта настройка мира влияет и на OBS; код не выключает её сам.
3. Для замедленной проверки установите **Fade In** и **Fade Out** длительностью **1200 ms**, **Linear** в общем дизайне, сохраните его. **Play Entrance Animation** должен изменить прозрачность от 0 к исходной; карточка остаётся видимой. **Play Exit Animation** должен постепенно уменьшить её до 0 и лишь затем скрыть. Снова нажмите Entrance.
4. Нажмите **Play Pulse Animation** дважды с паузой между нажатиями: вся карточка должна увеличиваться и возвращаться за 1200 мс. Постоянные координаты, размеры и поворот остаются прежними.
5. Для Slide настройте **Slide In Right**, 1200 ms, Linear и проверьте **Preview entrance**: смещение должно уменьшаться до нуля. Верните желаемые типы/длительности после проверки.
6. **Next Page** должен использовать настроенный переход страницы; **Next Character** — отдельный переход персонажа. Затем **Resume Carousel**: проверить автоматический полный цикл, соответствие имени/портрета/полей одному персонажу. Текущие длительности демо могут быть 400/600 мс — код не заменяет их на 1200 мс.
7. Проверьте Flash и Glow отдельно через Emphasis → Preview. После тестового Exit сначала верните карточку Entrance; после обычного Hide включите видимость слоя.
8. Включите **Animation and carousel debug mode**, повторите эффекты, нажмите **Refresh diagnostics**. `playback` и консоль покажут target/connected/duration/opacity/transform и `requested`, `started`, один `sample`, затем `finished` или `cancelled`. При блокировке будет `skipped` с причиной. Для Fade с Linear ожидается промежуточная прозрачность между 0 и исходной, для Pulse — матрица с масштабом около 1,12 в середине, затем исходная матрица. Выключите debug после проверки.
9. Сохраните оверлей и выберите его в **Active on stream**. В тестовой панели выберите **OBS (saved active overlay)**. Повторите вход/выход/Pulse, страницы и персонажей в настоящем Browser Source. Проверяйте сам источник: подтверждение команды не доказывает видимый эффект. Предпочтение reduced motion следует проверить именно в OBS, поскольку оно зависит от клиента.

Существующий изолированный проверочный экран запускается из папки модуля командой `node work/serve-browser-harness.mjs`, адрес `http://127.0.0.1:30001/stream?mso=1`. **Measure animations** собирает точки 0/300/600/1000/1300 мс для Fade In/Out, Pulse дважды, Slide, Flash и Glow, затем автоматические переходы. По умолчанию экран соблюдает реальный reduced motion и объясняет блокировку. Снятие флажка **Respect reduced motion** влияет только на изолированную проверку; настройки мира и Windows не меняются. Этот экран тоже требует разрешённого локального соединения и не заменяет проверку полного Foundry/OBS.
