# Отчёт об исправлении анимаций и демонстрации — 0.5.4

Это исторический отчёт 0.5.4. Его проверки Fade/Pulse подтверждали наличие Web Animations и конечную видимость, но не измеряли промежуточные computed styles. Они не доказывают видимость эффектов при системном reduced motion. Текущее расследование и точные границы проверки находятся в [ANIMATION_FIX_REPORT.md](ANIMATION_FIX_REPORT.md).

Работа выполнена в действующем модуле:
`C:\Users\Lev\AppData\Local\FoundryVTT\Data\modules\modular-stream-overlay`.
Путь подтверждён через `Config/options.json` и manifest модуля. Отдельный модуль или альтернативный renderer не создавался. Прямых записей в базы миров, настоящие Actors, `storage/` и пользовательские изображения не выполнялось.

## Что было сломано и почему

| Проблема | Причина | Исправление и проверка |
| --- | --- | --- |
| Настроенный Fade In не запускался при первом открытии вывода | Первичная сборка сцены подавляла все входы вместе с историческими одноразовыми реакциями | Настроенный вход запускается после подключения видимой внешней сцены к DOM. Подготовленные скрытые карточки не дублируют вход. Проверено тестами и настоящей Web Animation 600 мс в браузере |
| После тестового выхода вход не возвращал виджет | Метод входа восстанавливал внутренний флаг, но не `style.visibility`; запоздавший выход также мог завершиться после нового входа | Вход восстанавливает видимость, отменяет старый канал и инвалидирует прежнее завершение выхода. Проверены скрытие и повторное появление в браузере и регрессии |
| Локальные команды тестирования/Preview Character могли отклоняться | В командах отсутствовал ID текущего оверлея, обязательный для production-диспетчера | Редактор передаёт идентичность текущего черновика. Проверены настоящий обработчик и разделение локального черновика / сохранённого OBS-вывода |
| Часть числовых переходов общего шаблона терялась внутри страниц | При создании вложенного renderer страницы настройки перехода родителя не передавались дальше | Страницы наследуют value transition родителя. В браузере измерены промежуточные ширины полосы и значения текста |
| Не было понятного законченного примера и полной проверки отдельных осей | Существующие ручные команды в основном перемещали общую последовательность; не было установленного обычного контента для воспроизведения сценария | Добавлены редактируемое демо, команды отдельно для страниц и персонажей и штатные Animation Test Controls, использующие существующие движки |

Предыдущая ошибка транспорта `/stream` исправлена в 0.5.3 и сохранена: новые команды используют тот же аутентифицированный module socket, проверку отдельного sender ID от сервера, срок действия и ограниченную память. Смена страниц сама по себе не отправляет повторные команды и не записывает настройки на каждом шаге.

## Созданное содержимое

- **Demo — Animated Character Showcase**, 1920 × 1080: фон, заголовок и один групповой виджет.
- **Demo — Animated Character Card**: общий портрет/имя/рамка, страницы **Main Information**, **Additional Information**, **Visual Showcase** с номерами страниц.
- Fade In/Out 600 мс, Slide Left 400 мс, смена персонажа Fade 600 мс суммарно, Pulse 800 мс, HP-вспышки и плавные значения 600 мс.
- Режим **DEMO DATA — simulated characters**: Demo Warrior 75/100 и Demo Mage 40/60. Данные находятся только в памяти; никаких фиктивных Actors или изменений настоящих характеристик.
- Единый комбинированный цикл, Pages First, три страницы по 4 секунды, Loop. Портрет, имя и поля подготавливаются вместе для одного персонажа.
- Безопасная повторная установка: открытие существующего демо сохраняет изменения, сброс требует отдельного явного действия. Действующий эфир при установке не переключается.
- Необязательная диагностика, выключенная по умолчанию: идентификаторы, состояние, последнее правило/анимация, недоступные привязки. Значения характеристик не включаются в production-диагностику.

## Как открыть и проверить

В Foundry как GM: **Open Overlay Editor → Install Demo Overlay**. После установки кнопка называется **Open Demo Overlay**. Для общего дизайна выделите карточку → **Edit shared design**. Для настоящих персонажей переключите **Character data source → Foundry Actors**, используйте **Add Character**, настройте порядок и сохраните оверлей. Аккаунту вывода нужны права Observer.

В **Animation Test Controls** выберите карточку и **Editor preview**. Проверьте вход, выход, Pulse, Next/Previous Page и Character, Pause/Resume и Restart. После выхода используйте вход для возврата карточки. **Restart Carousel** сохраняет текущую паузу. Симуляция урона/лечения доступна только в DEMO DATA.

Для OBS выберите демо в **Active on stream**, настройте выделенного Player, используйте **Sign-in URL** для входа через Interact, затем **Browser Source URL** с `/stream?mso=1`. Размер источника — 1920 × 1080. Выбор **OBS (saved active overlay)** отправляет тестовые команды этому сохранённому выводу; черновик сначала необходимо сохранить.

Полная инструкция: [DEMO_GUIDE.md](../DEMO_GUIDE_RU.md).

## Что ещё требует ручной проверки

В доступной среде не было авторизованного запущенного мира Foundry и управляемого OBS. Поэтому **не заявляется** успешная проверка:

- полного окна ApplicationV2, установки кнопкой и перезагрузки именно в вашем действующем мире;
- живых изменений настоящих Actors вашей системы и их фактических прав Observer;
- полного сетевого пути GM → сервер Foundry → отдельная сессия OBS, входа Interact, перезагрузки/переподключения OBS;
- визуального результата в установленной версии OBS и отсутствия сторонних CSS-помех других модулей.

Production-путь `main.js`/`streamReady` и аутентификация проверены в интеграционном окружении, а production renderer и реальные браузерные анимации — отдельно в браузере. Это более узкие проверки, чем полный прогон Foundry + OBS. Для завершения проверки на вашей машине выполните шаги OBS из руководства; при проблеме включите debug и сохраните сообщение об ошибке без полного содержимого Actor.
