# Демо анимированной карточки персонажа

Версия модуля: **0.6.0**, Foundry VTT **14**. Рабочая папка:
`Data/modules/modular-stream-overlay` в папке пользовательских данных Foundry.

Демо использует обычные слои, общий шаблон виджета, привязки данных, движок анимации и единый контроллер карусели модуля. Его можно редактировать и применять в собственных оверлеях.

## A. Установка и открытие

1. Перезапустите Foundry после обновления модуля, откройте мир и обновите клиент GM и Browser Source в OBS.
2. Войдите как GM. В Settings откройте **Open Overlay Editor**. Также редактор доступен через настройку **Modular Stream Overlay**.
3. В левой колонке нажмите **Install Demo Overlay**.
4. Откроется **Demo — Animated Character Showcase**, холст **1920 × 1080**. Будет выделен виджет **Demo — Animated Character Card**.
5. В его настройке **Character data source** изначально выбран **DEMO DATA — simulated characters**. На карточке отображается пометка **DEMO DATA**.
6. В предпросмотре автоматически меняются три страницы и два тестовых персонажа. Настоящие документы Actor при этом не создаются и не изменяются.
7. Чтобы вывести сохранённое демо в OBS, выберите **Demo — Animated Character Showcase** в списке **Active on stream**. Установка сама не переключает действующий эфир.

Повторное открытие выполняется кнопкой **Open Demo Overlay**. Новые копии не создаются, ваши изменения сохраняются. Кнопка **Reset Demo Overlay** после отдельного подтверждения восстанавливает исходные настройки демонстрационного оверлея и его общего шаблона. Остальные сохранённые оверлеи и шаблоны не перезаписываются. Экземпляры, использующие этот общий демонстрационный шаблон, также увидят его восстановленный дизайн.

Программная установка для GM, если она нужна в макросе:

```js
await game.modules.get("modular-stream-overlay").api.installDemo();
```

Макрос устанавливает или находит демо; окно удобнее открывать штатной кнопкой редактора. Никакая установка не выполняется при каждом запуске Foundry.

## B. Общий шаблон и информационные страницы

Выделите карточку на холсте и нажмите **Edit shared design**. Другой путь: **Widget Preset Manager** → **Demo — Animated Character Card** → **Edit / preview**.

В разделе **Information pages** список **Edit content** содержит **Shared elements** и три страницы:

| Страница | Содержимое |
| --- | --- |
| **Main Information** | Текущий и максимальный HP, плавная полоса здоровья, если активный адаптер поддерживает HP |
| **Additional Information** | Дополнительные числовые поля и ресурсы действующего адаптера; для CAIN — Level, Power, Stress, Psyche |
| **Visual Showcase** | Статический текст и видимый повторяющийся Pulse 800 мс |

Портрет, имя, рамка и обозначение типа персонажа находятся в **Shared elements** и остаются на месте при переключении страниц. Внизу каждой страницы есть редактируемая подпись с её номером и названием.

Для проверки без настоящего Actor нажмите **Preview DEMO DATA**. **Preview with character** выбирает настоящего персонажа только для локального предпросмотра шаблона; этот выбор не сохраняется в общий дизайн.

Для изменения страницы выберите её в **Edit content**, выделите слой на холсте или в **Layers** и измените **Properties**. Кнопка **Add page** создаёт страницу; **Rename page**, **Duplicate page**, **Earlier**, **Later**, **Delete page** управляют выбранной страницей. **Enable this information page** включает её в показ. В **This page duration (seconds; blank uses default)** задаётся время именно этой страницы.

Чтобы создать собственный шаблон, откройте **Widget Preset Manager** → **Create widget preset**. Добавляйте компоненты штатными инструментами и сохраняйте кнопкой **Save widget design**. Затем в любом оверлее используйте **Add widget**, выберите этот шаблон и назначьте Actor. Общий шаблон хранит дизайн; список персонажей и положение на экране принадлежат экземпляру.

Для динамического компонента выберите **Content source → Dynamic character data**. **Character field** задаёт нормализованное поле. Для полосы дополнительно задайте **Maximum field**. В **Text template (blank uses field)** можно написать, например, `HP {character.hp.current} / {character.hp.max}`. **Insert field** вставляет доступное поле. **Missing value text** задаёт замену отсутствующего значения.

Список полей формируется адаптером текущей системы и пользовательскими mappings. Поля других систем не предполагаются автоматически. Если адаптер предоставляет только имя и портрет, демо всё равно содержит три работающие страницы; вместо неподдерживаемых HP и числовых ресурсов используются пояснения и тип персонажа. Для добавления собственных поддерживаемых полей есть **Advanced field mappings** в менеджере шаблонов.

После редактирования нажмите **Save widget design**. Связанные экземпляры используют сохранённый общий дизайн, сохраняя свои назначения персонажей и координаты. В режиме просмотра страниц **Edit selected content** возвращает возможность редактировать холст.

## C. Настоящие персонажи и DEMO DATA

В редакторе оверлея выделите карточку. Настройка **Character data source** предлагает:

- **DEMO DATA — simulated characters**: Demo Warrior с HP 75/100 и Demo Mage с HP 40/60. Это отдельные скалярные данные в памяти браузера, без документов Foundry.
- **Foundry Actors**: настоящие мировые Actors, доступные выбранному аккаунту вывода.

Для реальных персонажей:

1. Выберите отдельный аккаунт для OBS (любая роль) в поле **Viewer account** и нажмите **Save viewer**.
2. Дайте этому аккаунту право **Observer** на нужных Actors через штатные права Foundry.
3. Переключите **Character data source** на **Foundry Actors**.
4. В **Carousel Settings → Assigned Characters** нажмите **Add Character**. Выберите Actor в окне **Assign character**, вставьте `Actor.…` или ссылку Foundry. Повторите для второго персонажа. Также можно перетащить Actor из каталога на карточку или список назначений.
5. **Select Actor 1**, **Select Actor 2** заменяют соответствующую запись; **Earlier character 1**, **Later character 1** меняют порядок; **Remove character 1** удаляет назначение. Числа соответствуют строкам списка.
6. **Preview Character 1** или **Preview Character 2** переключают локальное представление, не изменяя Actor.
7. Нажмите **Save overlay**. Убедитесь, что этот оверлей выбран в **Active on stream**.

Прежние назначения настоящих Actors временно запоминаются при переключении источника в одном открытом редакторе. После сохранения в режиме DEMO DATA и перезагрузки назначьте реальных Actors снова: скрытый список реальных документов в демонстрации не сохраняется.

Режим DEMO DATA можно включить для экземпляра того же шаблона без его перестройки. **Restore demo characters** возвращает обе тестовые записи после их удаления из списка. Список и порядок сохраняются с экземпляром, а не с общим шаблоном.

**Simulate Damage** и **Simulate Healing** меняют только тестовые значения в текущем браузере вывода. Изменения не записываются в Actors, шаблоны или мировые настройки и сбрасываются при полной перезагрузке браузера. Предпросмотр редактора и OBS имеют отдельную память тестовых значений. Чтобы выполнить симуляцию в OBS, выберите OBS в **Test output**.

## D. Анимации и тестовые кнопки

В общем дизайне раздел **Whole widget animations & triggers** управляет карточкой целиком. Настройки выделенного компонента находятся в его **Properties**. В экземпляре оверлея флажок **Inherit shared widget animations and triggers** сохраняет наследование настроек общего шаблона; отключайте его только для отдельных переопределений.

В параметрах анимации выберите **Animation type** и укажите **Duration (ms)**, **Delay (ms)**, **Easing**. **Preview entrance**, **Preview exit**, **Preview emphasis** запускают локальную проверку. **Reset temporary effects** снимает временные эффекты. Сохраните общий дизайн через **Save widget design**, отдельные изменения экземпляра — через **Save overlay**.

Настройки демонстрации:

| Эффект | Настройка |
| --- | --- |
| Вход карточки | Fade In, 600 мс, в том числе при первом открытии вывода |
| Выход карточки | Fade Out, 600 мс |
| Смена информационной страницы | Slide Left, 400 мс |
| Смена персонажа | Fade, 600 мс суммарно: выход 300 мс и вход 300 мс |
| Акцент | Pulse, 800 мс |
| Уменьшение HP | Красный Color Flash на полосе HP, 400 мс |
| Увеличение HP | Зелёный Color Flash на полосе HP, 400 мс |
| Новое значение HP | Плавное изменение полосы и чисел, 600 мс |

В редакторе оверлея под холстом расположен раздел **Animation Test Controls**. Сначала выберите **Test widget**, затем **Test output**:

- **Editor preview** проверяет текущий черновик локально.
- **OBS (saved active overlay)** отправляет команду сохранённому активному оверлею. При несохранённых изменениях редактор попросит сначала выполнить Save; незаметная отправка черновика в эфир исключена.

| Кнопка | Действие |
| --- | --- |
| **Play Entrance Animation** | Воспроизвести настроенный вход; вернуть карточку после тестового выхода |
| **Play Exit Animation** | Воспроизвести выход и временно скрыть карточку |
| **Play Pulse Animation** | Увеличить всю карточку 1 → 1,12 → 1 за 1200 мс; настройки сохранённого акцента не изменяются |
| **Next Page / Previous Page** | Сменить страницу текущего персонажа |
| **Next Character / Previous Character** | Сменить персонажа с сохранением текущей страницы, когда она доступна |
| **Pause Carousel / Resume Carousel** | Приостановить последовательность / продолжить оставшееся время |
| **Restart Carousel** | Вернуться к начальной паре персонаж/страница; текущая пауза сохраняется |
| **Simulate Damage / Simulate Healing** | Уменьшить / увеличить HP синтетического персонажа на 10; доступны только в DEMO DATA |

После **Play Exit Animation** нажмите **Play Entrance Animation**, чтобы продолжить видеть карточку. После **Restart Carousel**, выполненного на паузе, нажмите **Resume Carousel**. Пауза карусели останавливает смену информации, а не все декоративные анимации.

Если движение отсутствует, посмотрите сообщение под кнопками. При **Enable overlay animations** и **Respect reduced motion**, включённых по умолчанию, браузер с системным запросом уменьшения движения намеренно пропускает эффекты. Чтобы осознанно разрешить анимации оверлея, GM может снять **Respect reduced motion** в настройках модуля; это настройка мира и затрагивает его клиенты, включая OBS. Модуль сам её не меняет. Настройки Windows и уменьшения движения браузера также остаются под вашим управлением. **None** во входе/выходе означает отсутствие эффекта и теперь объясняется тестовой панелью.

Для медленной визуальной проверки временно задайте в общем дизайне **Fade In / Fade Out → 1200 ms**, **Easing → Linear**, сохраните дизайн и проверьте вход, выход, повторный вход и Pulse. Для Slide выберите **Slide In Right**, проверьте **Preview entrance** и возврат в исходное положение. После проверки верните желаемые длительности. Кнопки входа/выхода всегда используют настроенную длительность; Pulse в тестовой панели специально длится 1200 мс.

Для настоящего Actor проверяйте HP штатным редактированием его листа только по собственному решению. Тестовые кнопки модуля не изменяют настоящие показатели.

## E. Комбинированный цикл

Для демонстрации уже заданы три страницы по **4 секунды**, автоматическое воспроизведение, повтор и **Pages First**. Один экземпляр карточки последовательно показывает:

`Demo Warrior / Main Information → Additional Information → Visual Showcase → Demo Mage / Main Information → Additional Information → Visual Showcase → Demo Warrior / Main Information`.

Для двух страниц и двух ваших персонажей последовательность выглядит так:

`A / Page 1 → A / Page 2 → B / Page 1 → B / Page 2 → A / Page 1`.

Настройки экземпляра находятся в **Carousel Settings**:

| Поле | Значение и влияние |
| --- | --- |
| **Cycling Mode** | **Combined — all pages for each character** для полного цикла. **Information Only** меняет страницы одного персонажа. **Character Only** меняет персонажей на одной странице. **Static** фиксирует одну пару |
| **Automatic playback** | **Play automatically** запускает цикл; **Start paused** оставляет ручное управление. **Use preset default** наследует общий шаблон |
| **Traversal Order** | **Pages First — A/1, A/2, B/1, B/2** перебирает страницы каждого персонажа; **Characters First** перебирает персонажей внутри каждой страницы |
| **Initial Actor** | Начальный персонаж из назначенного списка |
| **Information Page Order** | Порядок страниц экземпляра; **Use preset page order** возвращает порядок дизайна |
| **Initial information page** | Начальная информационная страница |
| **Page Duration (seconds; blank inherits)** | Длительность по умолчанию; поле с названием конкретной страницы переопределяет её время |
| **Page Transition** | Эффект смены страниц; **Page transition duration (milliseconds; blank inherits)** — его длительность |
| **Character Transition** | Эффект смены персонажа; **Character transition duration (milliseconds; blank inherits)** — его длительность |
| **Loop** | **Loop** повторяет последовательность, **Stop after the last step** останавливает её в конце |

В общем шаблоне аналогичные значения задаются в **Information pages → Cycling settings**: **Enable automatic cycling**, **Default cycling mode**, **Traversal order**, **Default page duration (seconds)**, **Page transition**, **Transition duration (milliseconds)**, **Character transition**, **Character transition duration (milliseconds)**, **Loop pages**, **Starting page**.

**Preview Sequence** показывает порядок с доступными именами персонажей. Не включайте **Skip this page when no dynamic information is available** для чисто декоративной страницы, которую нужно показывать всегда. Недоступные или удалённые Actors исключаются из показа. Для общей последовательности работает один планировщик; отдельного конкурирующего таймера смены персонажей нет. После перехода начинается полный период показа следующей страницы.

## F. OBS Browser Source

1. В редакторе выберите отдельный аккаунт для OBS в **Viewer account** → **Save viewer**. Помощнику ведущего доступ к персонажам выдавать не нужно; игроку дайте права Observer на нужных персонажей.
2. Скопируйте **Sign-in URL**, откройте его в Browser Source OBS через **Interact** и войдите этим аккаунтом. Вход в обычном браузере не авторизует OBS.
3. Скопируйте **Browser Source URL** штатной кнопкой редактора и вставьте в свойства источника. Обычно адрес имеет вид `http://localhost:30000/stream?mso=1`; используйте адрес, который показан у вас. Пароли и токены в URL не добавляются.
4. Отключите **Local file**, задайте размер **1920 × 1080**. Для непрерывной работы выключите **Shutdown source when not visible**.
5. В редакторе выполните **Save overlay** и выберите демо в **Active on stream**.
6. Проверьте появление карточки, три подписи страниц и смену Demo Warrior / Demo Mage. В **Animation Test Controls → Test output** выберите **OBS (saved active overlay)** и проверьте Pause, Next Page, Next Character, Pulse и вход/выход.

После обычного сохранения дизайна или оверлея OBS обновляется через существующие настройки Foundry. После обновления файлов самого модуля требуется обновление клиентов, а после изменения manifest/socket — перезапуск Foundry. При потере соединения модуль очищает вывод, после восстановления перечитывает сохранённую конфигурацию. Сохранённая конфигурация восстанавливается; временная позиция, пауза и симулированный HP не сохраняются как команды для будущего воспроизведения.

В настоящем `/stream?mso=1` редактор, ручки изменения размеров и диагностическая панель на эфир не выводятся. Тестовый браузерный стенд разработчика содержит отдельную панель управления для проверки и не является адресом для OBS.

## G. Диагностика и устранение проблем

**Animation and carousel debug mode** в **Animation Test Controls** по умолчанию выключен. Включите его и нажмите **Refresh diagnostics**. Помимо текущего персонажа, страницы, таймера и привязок, `playback` показывает последние запросы, реальный старт, один промежуточный замер, завершение/отмену или причину пропуска. В записи есть ID слоя, описание DOM-цели, её подключение к документу, длительность, вычисленные `opacity`/`transform` и причина отмены, например `render-interrupted`. Полная последовательность событий доступна в консоли браузера. Значения характеристик и полные документы не включаются. При выключенном debug промежуточные замеры и журналы не выполняются.

Панель показывает локальный предпросмотр редактора; при выборе OBS об этом есть отдельное пояснение. Диагностика самой страницы вывода доступна в её консоли через `game.modules.get("modular-stream-overlay").api.getDiagnostics()`, когда debug включён. Консольные сообщения записываются по событиям, не на каждом кадре. После проверки выключите debug.

| Проблема | Что проверить |
| --- | --- |
| Карточка невидима | Видимость слоя, ненулевая прозрачность и размеры; после тестового выхода — **Play Entrance Animation**. Есть ли общий шаблон, персонажи и хотя бы одна включённая страница? |
| Анимация не играет | В настройках модуля включено **Enable overlay animations**; при **Respect reduced motion** браузер может намеренно отключить движение. Проверьте, что выбранная входная/выходная анимация не None, длительность больше нуля и эффект наследуется ожидаемым образом |
| Страницы не меняются | **Cycling Mode** допускает страницы, **Automatic playback** включён, хотя бы две страницы включены. После паузы нажмите **Resume Carousel**. Для статической страницы отключите пропуск при отсутствии динамических данных |
| Персонажи не меняются | Назначено не меньше двух разных персонажей; выбран Combined или Character Only; у аккаунта вывода есть права. При Pages First смена персонажа происходит после всех его страниц |
| Нет HP или ресурса | Поле должно поддерживаться текущим адаптером и присутствовать у Actor. Проверьте **Character field**, **Maximum field**, права Observer и `missingBindings`. Неподдерживаемая полоса не изображает выдуманные значения |
| OBS не обновляется | Выполнены оба сохранения: **Save widget design** для общего дизайна и **Save overlay** для экземпляра. Выбран правильный **Active on stream**, источник авторизован выбранным аккаунтом вывода и использует URL с `mso=1` |
| Команда OBS не подтверждается | Открыт и загружен Browser Source. Вход в обычной вкладке игры не заменяет страницу вывода. После обновления модуля перезапустите Foundry и обновите OBS и GM-клиент. Старые команды не ставятся в очередь |
| Неверная конфигурация демо | Сначала **Open Demo Overlay**. Для возврата к исходному примеру используйте **Reset Demo Overlay**, учитывая предупреждение о сбросе двух демонстрационных записей. Существующие пользовательские оверлеи не заменяются |

Краткий список проверки: правильный viewer → права Observer → сохранённый дизайн → сохранённый активный оверлей → источник данных → два персонажа → включённые страницы → Combined / Pages First → автоматический запуск и Loop → правильный URL OBS.

## Что фактически проверено

Автоматические тесты выполняют установку и повторную установку, сохранение пользовательских изменений, восстановление хранилищ, совместимость старых данных, разрешения, реальный диспетчер команд, триггеры, таймеры и порядок переходов. В 0.5.4 браузерный стенд с **production OverlayRenderer** проверял полный цикл, паузу, HP и наличие Web Animations, но промежуточная прозрачность/масштаб Fade/Pulse тогда не измерялись. Для 0.5.5 подтверждён реальный браузерный запрос reduced motion; повторная визуальная проверка заблокирована локальным сетевым доступом. Точные результаты, причины и оставшиеся проверки приведены в [отчёте 0.5.5](internal/ANIMATION_FIX_REPORT.md).

Это не утверждение о завершённой проверке OBS или авторизованного мира Foundry. Полная проверка окна ApplicationV2 в запущенном мире, настоящих Actors и OBS Browser Source остаётся ручным шагом на вашей установке. Подробности исправлений и проверок находятся в [docs/DEMO_VERIFICATION.md](internal/DEMO_VERIFICATION.md).

## CAIN: отдельные примеры в версии 0.6.0

В **Widget Preset Manager** нажмите **Install CAIN examples**. Это отдельная установка: прежний анимационный Demo Overlay продолжает использовать свои синтетические данные. Новая кнопка добавляет **CAIN — Exorcist Card**, **CAIN — Compact Status** и неактивный **CAIN — Character Examples**. Повторная установка сохраняет ваши изменения и назначения Actors.

Назначьте настоящего world CAIN Character экземпляру карточки через Carousel Settings. У основного дизайна четыре страницы: Condition, Resources, Skills и Progression. Shared elements содержат портрет, имя, CAT/Psyche и XID. Для нескольких Characters выбирайте Combined. Установка не создаёт Actors и не включает новый оверлей в эфир автоматически.

Поля выбираются по подписи в каталоге, без ввода JavaScript-путей. Для полосы кнопка **Use matching maximum** явно выбирает объявленный максимум; смена поля сама не заменяет ваш maxBinding. **Data provider** выбирает системный адаптер; **Advanced field mappings** позволяет задать scope и прочитать несохранённый результат под правами аккаунта вывода.

Сначала проверьте нужный Actor в безопасном локальном preview, затем сохраните назначение. Неизвестная версия системы или неподходящий Actor type дают недоступность новых полей, а не выдуманные нули. Подробности: [CAIN.md](CAIN.md), [DND5E.md](DND5E.md), [Phase 6 acceptance](internal/PHASE6_ACCEPTANCE_RU.md).
